# Debrio functional demo

A local, self-contained product prototype based on `docs/Debrio_PRD_v0.5.md`. It is separate from the future production application. No installation, accounts, network assets, API keys, or paid services are needed.

## Open

Open **index.html** in Chrome or Edge. The demo opens on the supplied landing-page design. **Explore demo** enters the device-check lobby; **Website** on the Workshops screen returns to the landing page. Existing `#lobby`, `#run` and other app links still open directly. For the most reliable camera/microphone permission handling, run this from the repository root:

```powershell
npm --prefix demo start
```

Or, from this folder:

```powershell
npm start
```

Then visit http://127.0.0.1:4173. Stop the local server with Ctrl+C.

## Camera, microphone and waiting-room music

1. In the lobby, press **Turn camera on** and allow the browser request. Your actual camera appears in the preview and in the meeting's **You** tile.
2. Press the **microphone icon** and speak. The input meter measures the selected microphone. Click **Test sound** beside the speaker selector to open **Sound check**, then use **Hear myself** with headphones for live playback. It is off by default and records nothing.
3. **Test speakers** in Sound check plays a short two-tone sound. Select a speaker in the third device row when supported by the browser; otherwise use your operating system's sound settings.
4. Switch to **Participant**, then **Ask to join**. The supplied `Debrio_Lobby_music.wav` plays while you wait. Pause is beside the waiting controls; volume is in Sound check. **Admit me (demo)** enters the session and stops the music.
5. **Mute** and **Camera off** stop the corresponding device tracks. Navigating to Build/Review/Settings, ending the session, or closing the page releases both devices. The bottom dock's **More** menu offers **Camera & microphone** to return to the lobby check.

Blocked, missing, busy and disconnected devices show recovery instructions. Devices are never requested on page load. Browser permission is required even though this is a local demo. Device lists populate after a successful permission request. Real-time local preview is not a multi-person call: there is no media server or peer connection.

Appearance follows the supplied mockup and landing page: original square-and-dot mark, Public Sans, charcoal/mineral-grey surfaces, compact rail, restrained teal and a light/dark toggle. Control placement follows the mockup: Workshop label at top-left, role switch at top-right, three stacked device rows in the lobby, timer and visible agenda in Activity, and a full-width bottom dock. Polls open from their own dock button.

The file URL and server URL have separate browser storage. Workshop work is saved in `debrio-demo-v1`. The rail's **Reset demo** restores the sample workshop after confirmation. Only one tab should edit a rehearsal at a time.

## Explore the full journey

1. **Workshops:** click the Debrio logo to edit or open the seeded workshop, or create a fresh custom workshop. This prototype holds one workshop at a time; creating one explicitly replaces the current rehearsal.
2. **Build:** edit and reorder activities, change timing and instructions, inspect assignments, or add custom, peer instruction, role practice, and jigsaw sequences from Templates.
3. **Run:** admit waiting participants under People. Start/pause/extend the timer. Advance an activity with confirmation. Visit the breakout overview to Listen, Speak, Join, or resolve help. Send an announcement from the rooms or Messages panel.
4. **Participant preview:** switch roles at top-right and choose a fictional participant in the Rooms panel. Submit individual work, vote, request help, use released resources, and approve/withdraw sharing for an exact response. During home/expert work, everyone can edit the local group draft; only its assigned recorder submits the group snapshot.
5. **Practice:** advance to a role-practice stage. Resources follow the current practitioner/counterpart assignment. Rotate roles from the facilitator Activity panel. Submit another response during retry to preserve a linked revision.
6. **Jigsaw:** home groups become expert groups and return to the original home groups. Twenty sample participants produce five home groups of four or four expert groups of five. Role practice produces four trios and two groups of four.
7. **Review:** filter/search work, add checklist and written feedback, compare linked attempts, pin work, and present/download a debrief. Unapproved individual work can be pinned for planning but is excluded from presentation and the approved-debrief download.
8. **Resources and Settings:** create text resources, release or withdraw them, change workspace details, download CSV/JSON records, or reset.

The preloaded Review examples are illustrative records; they are not generated by live participants. Individual evidence, group output, and revisions remain distinct. There is no overall learning score.

## What works, and what is simulated

**Working locally:** camera preview, microphone capture/meter and optional live monitoring, device switching, speaker test, supplied lobby music with volume/pause, navigation, forms, template insertion, activity order, timers, grouping, role rotation, draft persistence, immutable attempt text and revision links, group snapshots with contributor IDs, feedback, version-specific sharing approval/withdrawal, polls, messages, help queues, text resources, debrief curation, and downloads.

**Simulated:** other people, admission, remote listening/speaking/joining, screen sharing, captions, and message delivery. No screen permission is requested and no email is sent. Camera and microphone are local only: no transmission or recording. Preview role selection is a demo control, not an authorization boundary.

**Outside this demo:** real authentication/MFA, multi-user synchronization, provider media, uploaded files/video, actual private-resource security, client invitations/publication, billing, retention enforcement, operational monitoring, and production deployment. The demo does not fulfill production release gates. Group drafts are shared across preview identities in one browser, not across devices. Do not enter personal or confidential information; anyone with access to this browser can inspect the demo data.

The sample agenda shows one practice pass; repeat practice/feedback/retry while rotating roles to rehearse every participant turn. It does not claim that the sample 67-minute agenda completes the full pilot protocol.

Unsaved activity, settings and message edits survive interface refreshes and view switches in the current tab. Use **Save** or **Send** before reloading. Participant responses retain their existing saved drafts.

## Checks

```powershell
npm test
node --check app.js
```

`model.test.cjs` covers grouping, role rotations, resource visibility, revision preservation and sharing, recorder-only submission, closed/empty submissions, and timer expiry. `browser-smoke.js` also checks the landing entry, links, local images, animation/reduced-motion behavior, responsive layout down to 320 pixels, and return from the workspace. `browser-smoke.js` and `media-smoke.js` are executable Playwright tool snippets (`browser_run_code_unsafe` with the file as `filename`). They use isolated browser contexts. Media checks inject synthetic video and audio sources, exercising the actual local video/AudioContext wiring without accessing physical devices. These checks do not prove physical microphone/camera compatibility, sound quality or echo control.

`ui-smoke.js` covers the Impeccable polish regressions: form drafts, keyboard focus, sound-check access, mobile panel clearance and long titles. The review is in `IMPECCABLE-REVIEW.md`.

Manual browser evidence and limitations are recorded in `VERIFICATION.md`. No production-media, concurrency, formal accessibility certification, or screen-reader testing is claimed.

## Files

- `landing.html`, `landing.css`, `landing.js`: supplied landing-page layout, local screenshot assets, working demo links and pausable hero animation.
- `index.html`, `styles.css`, `reference.css`, `app.js`: interface, supplied-reference styling, routes, and local interactions.
- `media.js`: opt-in local device/audio lifecycle. No recording or remote transport.
- `model.js`: synthetic fixture and instructional rules, shared with Node tests.
- `server.cjs`: optional loopback-only static server, using Node's standard library.
- `assets/`: original Debrio mark, Public Sans extracted from the supplied mockup (license included), and an unchanged copy of the supplied lobby WAV. Earlier Satoshi font assets remain from the first draft but are not the active font.

No production source, configuration, or provider settings were changed.

Browser implementation references: [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [media playback promises](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play), and [autoplay and user gestures](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).
